程式碼的家園之戰

從荷蘭開發者出走 GitHub，到英國 NHS 關閉公開儲存庫——一場關於程式碼該放在哪裡的大混戰，正在悄悄開打

2026 年 5 月 14 日  ·  數位主權  ·  GitHub  ·  開源

全球開發者圈正在掀起一場靜默的遷徙潮。程式碼——這個現代社會的基礎建設——存在哪裡、由誰控制、能否被 AI 拿去訓練，這些問題正在迫使個人開發者、企業乃至國家級機構重新思考他們的選擇。這不是一場單一的革命，而是幾股力量同時在不同角落燃起的野火。

故事一：荷蘭開發者的出走宣言

案例 · 2026 年 4 月底
荷蘭開發者 Jorijn 離開 GitHub——和荷蘭政府做了同樣的選擇

他在個人部落格詳述決策過程，時間點剛好與荷蘭內政部推出自架 Forgejo 平台同一週

2026 年 4 月 27 日，荷蘭內政部悄悄上線了 code.overheid.nl——一個用於托管政府開源程式碼的自架 Forgejo 實例。就在同一週，荷蘭開發者 Jorijn 也完成了自己的遷移，在部落格詳述了決策過程，將主要程式碼平台遷至自架的 code.jorijn.com，跑在一台 NUC 上的 Forgejo v15 LTS。

Jorijn 的文章開頭一句話直接點題：「不是因為服務中斷，而是因為誰擁有在那之上運行的一切。荷蘭政府剛做了同樣的結論。」

為什麼要走？

  • GitHub 的 AI 訓練政策翻轉：2026 年 4 月 24 日，GitHub 將 Copilot Free、Pro、Pro+ 的用戶互動資料預設改為「訓練 AI 用途的 opt-in」——而且沒有 repository 層級的退出選項。Jorijn 的結論：「我不擁有這個平台。荷蘭政府剛公布了同樣的結論。」
  • GitHub 已沒有自己的 CEO：2025 年 8 月，GitHub CEO Thomas Dohmke 離職，Microsoft 沒有補位，而是將 GitHub 整併進 Microsoft 的 CoreAI 部門——也就是負責打造 Copilot 與整個 AI 技術棧的同一個組織。
  • 美國法律管轄風險：FISA Section 702 與 CLOUD Act 的管轄範圍未解。Microsoft 的律師曾在法國參議院宣誓作證時承認，他無法保證歐盟用戶的資料不受美國政府的靜默存取。
  • 持續的服務中斷：2025 年 5 月至 2026 年 4 月，GitHub 共記錄了 257 起事故、48 起重大中斷，累積約 112 小時的停機時間。GitHub CTO 公開道歉並表示容量需要擴增 30 倍才能跟上「AI Agentic Workflow」帶來的負載。

他選擇了 Forgejo

Forgejo 是完全開源、社群治理的 Git 托管平台。Jorijn 自架在一台 NUC 上，Public GitHub repositories 的計畫是在遷移完成後改為封存並指向新位置。荒蕪 GitLab 是另一個選項，但他和荷蘭政府都選了 Forgejo——因為它是完全開源的，給予數位自主所需的所有自由。

服務中斷、AI 訓練的預設 opt-in、GitHub 不再有自己的 CEO——這些都只是同一個底層事實的症狀：我不擁有這個。

— Jorijn Schrijvershof，〈Why I'm leaving GitHub for Forgejo〉，2026 年 4 月

故事二：英國 NHS 關門大吉

案例 · 2026 年 5 月 5 日
NHS England 計畫關閉所有公開 GitHub 儲存庫

理由是 AI 安全疑慮——開源代碼可能協助攻擊者更有效率地找到漏洞

就在同一個月，大西洋對岸傳出了截然不同、卻同樣令人矚目的消息。英國國家醫療服務體系（NHS England）宣布計畫將旗下所有公開 GitHub 儲存庫改為私有，理由是 AI 安全疑慮。

NHS England 在 GitHub 上的儲存庫數量達數百個，內部指引要求在 5 月 11 日前全數由公開狀態改設為私有。根據 iThome 引述 The Register 的報導，這份指引的導火線十分具體：文件中明確點名了 Anthropic 的 AI 模型 Mythos，指出現在的 AI 模型已能大規模擷取程式碼並進行推論與分析，公開儲存庫中的原始碼、架構決策、組態細節都可能遭到濫用。

核心擔憂：AI 讓開源變危險了？

  • AI 輔助攻擊：開源代碼可能被用於訓練 AI 模型，讓攻擊者更有效率地找到 NHS 系統的漏洞與攻擊向量
  • 能力不對稱：在 AI 能力快速演進的情況下，過去「開源促進透明與安全」的邏輯可能已被翻轉

NHS 發言人確認了這項計畫，將其描述為「在 AI 能力持續演進的情況下，對管理開源程式碼儲存庫採取謹慎態度」。

開源社群的反彈

  • 「以隱晦求安全」的謬誤：安全研究者普遍認為，security through obscurity 並非可靠的防禦策略，遮蔽代碼不等於消除漏洞
  • 阻礙獨立研究：讓外部安全研究員無法審視代碼，可能反而使漏洞更難被發現和負責任地回報
  • 效果存疑：部分被關閉的 repo 本就基於廣泛流通的公開框架，轉私有的安全效益十分有限

NHS 表示將「持續觀察情勢」，若日後能建立適當安全措施，可能重新開放。

故事三：Ghostty 的出走

案例 · 2026 年 4 月 28 日
知名終端機專案 Ghostty 宣布遷離 GitHub

作者 Mitchell Hashimoto 是 Vagrant 與 Terraform 的創始人，用 18 年的感情寫下這篇告別文

2026 年 4 月 28 日，開源終端機模擬器 Ghostty 宣布將主要開發平台從 GitHub 遷走。作者 Mitchell Hashimoto 是知名基礎設施工具 Vagrant 和 Terraform 的創始人，他在 GitHub 上是第 1299 號用戶，從 2008 年起每天都在用，超過 18 年。

這篇文章並非冷靜的技術評估，而更像一封充滿情緒的告別信。他寫道：「GitHub 是讓我最快樂的地方⋯⋯我愛 GitHub 的程度超過一個人應該愛一件事的程度，而我現在對它很憤怒。」

為什麼要走？

  • GitHub 頻繁出狀況：Mitchell 連續一個月記錄每天 GitHub 故障影響工作的日期，幾乎每天都有。就在他寫下這篇文章的當天，GitHub Actions 就已中斷超過兩小時，讓他無法進行任何 PR review。
  • 平台已不再是嚴肅工作的場所：「如果一個平台每天都把你擋在門外好幾個小時，它就不再是能做嚴肅工作的地方了。」
  • AI 訓練數據問題：GitHub 將 Copilot 訓練政策改為 opt-out，而 Ghostty 的過去貢獻者們從未同意這件事。他的立場簡潔有力：「追溯同意，不算同意（Retroactive consent is not consent）。」

Mitchell 表示，Ghostty 將保留 GitHub 唯讀鏡像，但具體搬遷目的地仍在評估中（包含商業與開源方案）。他的個人專案暫時留在 GitHub，Ghostty 是第一步。

我可以繼續等它變好，但我也想寫程式。而我再也無法用 GitHub 寫程式了。對不起。在 18 年之後，我得走了。

— Mitchell Hashimoto，〈Ghostty Is Leaving GitHub〉，2026 年 4 月 28 日

深度分析：這不是孤立事件

Jorijn 的個人選擇和 NHS 的機構決策，表面上看似截然不同，但背後其實是三股力量同時湧起、交匯的結果。

①
AI 訓練數據焦慮

GitHub 上的程式碼已被大量用於訓練 Copilot 等工具。開發者發現自己的勞動成果在不知情的情況下成為商業 AI 的養料，不滿情緒正在累積。

②
數位主權意識崛起

後 GDPR 的歐洲對數據主權高度敏感。越來越多機構在問：「我的基礎設施能否不依賴美國科技公司？」替代方案因此備受關注。

③
公共機構的 AI 安全恐慌

NHS 代表一種新型焦慮：「開源讓 AI 有更多攻擊面」的反轉思維。若此邏輯蔓延，將深刻改變各國政府的開源策略。

兩條分叉的路，同樣的出發點

🟢 個人 / 小型開發者

追求自主、對齊開源價值，往 self-hosted 方向走。目標：從 GitHub 的中心化中解放，回到「我掌控我的工具」的狀態。

🔴 大型機構 / 公共部門

以安全之名，往封閉、私有化方向走。同樣是逃離中心化，但是為了鎖住代碼，而非解放它。

這兩個方向都在「逃離」GitHub 的中心化，但出於截然不同的理由、走向截然不同的結果。一個是為了自由，一個是為了封鎖。吊詭的是，他們恰好站在開源精神的兩個對立端點上。

程式碼的家住在哪裡？

GitHub 如今擁有超過 1 億開發者，是全球最大的程式碼托管平台。但它同時也是 Microsoft 的資產、Copilot 的訓練場、美國法律管轄的平台。這些事實一直存在，只是過去沒有人特別在意。

現在，AI 的崛起把這些問題全部從水面下逼了上來。

這場混戰還在初期。Forgejo、Codeberg、Gitea、自架 GitLab——替代方案都存在，但沒有一個擁有 GitHub 的網路效應。NHS 的做法會不會成為各國公共機構的模板？歐盟的數位主權政策會不會逼出更多「官方出走」？

可以預見的是：接下來幾年，「你的程式碼放在哪裡」這個問題，將不再只是技術決策，而是政治、商業與倫理的多重交匯點。

當程式碼成為基礎建設，托管程式碼的平台就成了基礎建設的基礎建設。我們從未認真討論過，這樣的權力該被誰掌握。

— 無名氏，某個 Hacker News 留言區
